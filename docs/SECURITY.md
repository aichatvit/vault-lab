# Модель угроз и границы защиты

## Защита VLAGOST2

Контейнер на обеих платформах и рабочая папка Linux хранят аутентифицированные зашифрованные данные.
Заголовок и индекс проверяются до использования метаданных. Проверка записи
привязывает блок к контейнеру, ID файла, позиции и ожидаемому тегу из индекса.
Полная корректная старая ревизия остаётся пригодной для чтения. Для выявления
такого отката требуется внешнее доверенное состояние.

В Windows папка CFAPI показывает имена и размеры в NTFS, может содержать расшифрованный кэш и локальные правки. После сбоя часть содержимого может быть доступна по правам профиля до повторного ввода ключа. [Ограничения защиты в Windows](WINDOWS.md#ограничения)

В Linux на носителе видны общий размер контейнера, размеры и количество рабочих файлов
и открытые служебные идентификаторы. Расшифрованные данные передаются
авторизованному приложению в памяти. Его собственные файлы и дампы ОС
защищаются отдельно. [Формат и границы доступа](SBOX_WINDOWS_READER.md#требования-к-защите-рабочей-папки-и-завершению-сеанса)

## Доверенные компоненты

Доверенные компоненты: ядро Linux, исполняемый файл, Rust-зависимости,
криптокрейт, нативный плагин, среда запуска и терминал ввода ключа.
Это описание реализации, а не заключение независимого аудита.

## Сценарии

| Действие противника | Поведение / предел |
|---|---|
| Читает закрытый контейнер без ключа | Имена и данные зашифрованы; ID и размер открыты |
| Меняет заголовок, IV, ciphertext или тег | Ошибка framing либо HMAC; данные не выдаются |
| Подставляет неверный ключ | Ошибка аутентификации корректного контейнера |
| Возвращает старый целый контейнер | Не обнаруживается, монотонного счётчика нет |
| Подставляет другое хранилище с тем же ключом | Внешнего закрепления ID нет |
| Удаляет контейнер или заполняет диск | Доступность не гарантируется |
| Меняет pathname после открытия directory FD | FD остаётся привязан к исходному объекту |
| Подменяет mountpoint после передачи FD в open | Контролируемый тест проверяет сохранение доступа к исходному FUSE |
| Получает root во время работы | Вне модели защиты: память, процессы и namespace доступны root |
| Подменяет бинарник или .so до запуска | Вне модели защиты; подписи при запуске не проверяются |

## Защита разрешения путей

`directory` использует `openat2` с `RESOLVE_NO_SYMLINKS`. Для операций
`beneath` добавляет `RESOLVE_BENEATH` и `RESOLVE_NO_XDEV`: путь остаётся ниже
закреплённого FD, не идёт через symlink или другое монтирование.
Все открытия добавляют `O_CLOEXEC`; клиенту отдельно передаётся только корень
через FD 3 с очищенным close-on-exec. `fstatfs` проверяет тип FUSE, но не
идентичность или криптографическую подлинность файловой системы.

В `open` служба создаёт новый mount namespace, делает распространение `/`
приватным и использует собственный tmpfs. Клиент не получает произвольный
внешний mountpoint как адрес записи. Он запускается из того же бинарника;
снижения привилегий клиента до обычного пользователя здесь нет.

`mount` использует обычную видимую точку и другой сценарий доступа.
`AllowOther` сочетается с `DefaultPermissions`, 0700/0600 и выбранными UID/GID.
Это не защита от root и не многопользовательская система ACL.

## Остаточные риски

Нет защиты от чтения памяти, swap, гибернации, гипервизора, перехвата терминала,
внедрения кода или входа root в namespace. `DIRECT_IO` и нулевой TTL уменьшают
кэширование FUSE, но не дают общего доказательства отсутствия plaintext-копий.
`get` явно выводит plaintext в терминал. Нет безопасного стирания накопителя,
серверного управления ключами, удалённой аттестации, TPM или anti-rollback.

Файл lock исключает случайное параллельное открытие. Противник с возможностью
заменить или удалить lock может обойти такую координацию. Формат не скрывает
размер дерева, частоту обновлений и факт наличия хранилища.

## Что подтверждено проверками

Автотесты проверяют отдельные контрольные векторы, round-trip и отказы на
изменённых данных. Они не доказывают стойкость плагина и не заменяют аудит.
Набор проверок Linux описан в [плане тестирования](TESTING.md). Полный FUSE
smoke требует окружения с /dev/fuse и разрешёнными монтированиями.

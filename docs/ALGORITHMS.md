# Алгоритмы работы

Криптографические примитивы исполняет плагин. Приложение реализует формат и
жизненный цикл файлов. В Linux сеанс управляет зашифрованной рабочей копией и атомарной заменой контейнера.

## Жизненный цикл VLAGOST2

1. Взять блокировку на отдельном служебном объекте, который переживает замену
   контейнера. Аутентифицировать и расшифровать индекс, проверить каждый блок
   по ожидаемому тегу и HMAC и записать шифротекст в рабочий файл. Открыть
   доступ после синхронизации рабочей копии и фиксации признака готовности.
2. Кэш записи хранит до восьми изменённых блоков по 1 МБ на сеанс. Чтение
   учитывает изменения в памяти. При вытеснении или синхронизации соседние
   блоки одного файла шифруются с отдельным IV для каждого блока. Основной
   и вспомогательный потоки используют собственные контексты, один писатель
   дописывает результаты по порядку. После синхронизации данных приложение
   атомарно публикует изменения метаданных. Синхронизируемая правка до
   4 096 байт внутри существующего блока может сохраняться в зашифрованном
   состоянии сеанса. При чтении она применяется после проверки базового блока.
   До восьми проверенных блоков остаются в кэше чтения. Попадание требует
   совпадения ожидаемого тега и всех байтов шифротекста с диска.
3. При закрытии зафиксировать буферы, объединить сохранённые мелкие правки
   с базовыми блоками и записать ожидаемую ревизию. Во время копирования
   сверять теги с индексом. После синхронизации временного контейнера заново
   прочитать его индекс и проверить HMAC каждого блока. Только затем сверить
   ревизию исходного контейнера, атомарно заменить его и синхронизировать каталоги.
4. После успешной замены удалить служебную копию. При сбое аутентифицировать
   рабочее состояние и прочитать текущую ревизию контейнера. При исходной
   ревизии повторить упаковку из зафиксированного рабочего индекса. При новой
   ревизии завершить очистку. При другой ревизии сохранить рабочую копию и
   сообщить о конфликте. Если сбой произошёл до признака готовности рабочей
   копии, начать распаковку заново из проверенного контейнера.

## Шифрование и проверка

Для каждого нового блока создаётся случайный IV. Плагин шифрует дополненные
по PKCS#7 данные и вычисляет HMAC контекста и шифротекста вместе с IV.
Ожидаемый тег сохраняется в зашифрованном индексе. При чтении проверяются
ожидаемый тег и HMAC, затем выполняются расшифрование и проверка дополнения.

`init` создаёт пустой контейнер без перезаписи существующего файла.
`check` проверяет индекс, точную длину контейнера и все блоки без распаковки.
При записи вспомогательный поток инициализирует свой контекст плагина в фоне.
Основной поток продолжает запись во время инициализации и может работать
самостоятельно при отказе вспомогательного контекста. Для ошибок инициализации
17, 506 и 507 выполняется до 16 попыток с независимыми случайными seed.
При повторном отказе основного контекста команда возвращает ошибку плагина.

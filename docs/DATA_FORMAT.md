# Формат хранения и модель данных

## VLAGOST2 — формат S-BOX

`VLAGOST2` — общий переносимый формат для Linux и Windows. Один файл содержит заголовок, зашифрованный индекс и зашифрованные записи пользовательских файлов. При открытии эти записи копируются в отдельные зашифрованные файлы в служебной папке. При закрытии приложение упаковывает актуальные записи обратно в один файл. Формат реализован в консольной утилите Linux. SD-Reader для Windows использует эту спецификацию как проект интеграции.

### Единицы и квота

- 1 МБ = 1 000 000 байт. 1 ГБ = 1 000 МБ = 1 000 000 000 байт.
- Положительная квота задаётся при создании, хранится как целое число байтов `u64` и применяется к сумме логических размеров файлов. Например, квота 10 ГБ соответствует 10 000 000 000 байт.
- Размер контейнера, объём рабочей копии и доступное место отображаются отдельно. На диске дополнительно занимают место индекс, IV, теги, выравнивание и временные файлы.
- Блок файла содержит до 1 МБ открытых данных. Последний блок может быть короче. У пустого файла блоков нет, размер его зашифрованной записи равен нулю. Максимальный размер открытого индекса составляет 64 МБ.

### Заголовок и расположение данных

Целые числа беззнаковые, многобайтовые числа записываются в little-endian. Смещения и длины в двоичной раскладке выражены в байтах.

| Смещение | Длина | Поле |
|---:|---:|---|
| 0 | 8 | ASCII `VLAGOST2` |
| 8 | 16 | Случайный ID контейнера |
| 24 | 16 | Случайный ID ревизии, новый при каждой упаковке |
| 40 | 4 | Длина IV `V`, от 16 до 128, совпадает с параметром криптоплагина |
| 44 | 8 | Длина шифротекста индекса `C`, положительная, кратная 16, не больше 64 000 016 |
| 52 | `V` | IV индекса |
| `52 + V` | `C` | Шифротекст индекса |
| `52 + V + C` | 32 | HMAC фиксированного заголовка, IV и шифротекста индекса |
| `84 + V + C` | По индексу | Записи данных подряд в порядке ID файлов, блоки внутри файла в порядке от нулевого |

Читатель проверяет ограничения длины до выделения памяти и проверяет HMAC до расшифровки индекса. Данные файлов начинаются сразу после тега индекса. Длина каждого шифрованного блока вычисляется по логической длине данных и правилам PKCS#7. Читатель вычисляет все диапазоны с проверкой переполнения и отклоняет усечение или лишние байты после последней записи.

### Зашифрованный индекс

Первые поля открытого индекса — квота (`u64`), следующий ID узла (`u64`) и число узлов (`u32`). Далее идут записи узлов по возрастанию ID. У каждой записи поля в следующем порядке:

| Поле | Тип |
|---|---|
| ID узла | `u64` |
| ID родительского каталога | `u64` |
| Тип | `u8`, 0 — файл, 1 — каталог |
| Длина имени | `u16`, от 0 до 255 байт |
| Логический размер | `u64`, для каталога 0 |
| Имя | Строго корректный UTF-8 указанной длины |
| Теги блоков | По 32 байта на блок файла в порядке следования. Число блоков выводится из логического размера. |

Корневой каталог имеет ID 1, родителя 1, пустое имя и нулевой размер. Остальные ID больше 1. Следующий ID строго больше всех имеющихся. Удалённые ID повторно не выдаются. Имена остальных узлов содержат от 1 до 255 байт UTF-8, исключают `.`, `..`, `/` и NUL. Пары из родительского ID и имени уникальны. Родитель каждого узла существует и является каталогом. Каждая цепочка родителей ведёт к корню. Проверяются квота, фактическая длина индекса и его полное потребление декодером. SD-Reader должен обнаруживать конфликты путей Windows до открытия дерева пользователю.

### Запись файла

Каждая запись содержит последовательность блоков вида `IV || ciphertext || tag`. Шифруются исходные байты файла. Длина шифротекста блока с `n` байтами открытых данных равна `16 × (floor(n / 16) + 1)`. Для новых блоков IV генерируется системным RNG. Контекст HMAC включает ID контейнера, ID файла, номер блока и логическую длину. Тег сравнивается также с ожидаемым тегом из аутентифицированного индекса. Это привязывает блок к конкретному содержимому текущей записи, включая случай подстановки корректного старого блока того же файла. [Ключи и входы HMAC](KEY_MANAGEMENT.md#ключи-vlagost2)

Рабочий файл использует ту же раскладку каждого блока. Порядок блоков при упаковке определяется индексом. При распаковке и упаковке приложение проверяет блоки и копирует шифротекст вместе с IV и тегом. Оно расшифровывает содержимое в памяти при чтении пользователем или изменении блока. Индекс и состояние сеанса записываются отдельно в аутентифицированном зашифрованном виде. Для файлов в служебной папке используются служебные имена по ID. [Жизненный цикл рабочей копии](SBOX_WINDOWS_READER.md#общий-сценарий-работы-в-linux-и-windows)

### Рабочая папка Linux

Контейнер `name.sbox` использует соседний файл блокировки `.name.sbox.lock` и рабочий каталог `.name.sbox.work` с режимом `0700`. Рабочий файл имеет имя вида `<ID в 16 hex>-<поколение в 32 hex>`. Поколение — случайный 16-байтовый идентификатор. Один файл на узел указан в зафиксированном состоянии. Во время записи предыдущая и новая версии могут существовать одновременно.

Файл `state` содержит 40-байтовый заголовок `VLAWORK2 || ID контейнера || ID сеанса`, IV, шифротекст и 32-байтовый HMAC заголовка, IV и шифротекста. Длина IV совпадает с контейнером. Открытое содержимое записи состоит из ID исходной ревизии (16 байт), флагов (1 байт), ID ожидаемой ревизии (16 байт, нули при сброшенном бите упаковки), длины открытого индекса (`u32`), индекса, 16-байтовых поколений файлов в порядке их ID и смещений блоков как `u64` little-endian по ID файла и номеру блока. Состояние без смещений означает последовательное размещение блоков, как при распаковке. Бит 0 означает, что приложение готовит или уже зафиксировало ожидаемую ревизию. Бит 1 отмечает изменения в рабочей копии. В полном снимке бит 3 указывает на сохранённые мелкие правки после массива смещений. Каждая состоит из ID файла и логического смещения (по `u64`), длины (`u16`) и байтов правки. Все целые поля little-endian. Весь снимок зашифрован и аутентифицирован. Наличие корректного `state` подтверждает, что рабочие файлы распакованы полностью.

Рабочий индекс поддерживает также журнал. При значении флагов 4 открытое содержимое `state` состоит из ID базовой ревизии (16 байт), флага (1 байт), ID контрольного снимка (16 байт), ожидаемого тега снимка (32 байта) и операций в порядке фиксации. Файл `checkpoint-<ID в 32 hex>` содержит предыдущий полный зашифрованный снимок. Он записывается и синхронизируется до публикации первого журнала. При открытии проверяются тег снимка, ID сеанса, ревизия, обе аутентифицированные записи и итоговое дерево. Незавершённое обновление оставляет прежний или новый журнал. При достижении порога приложение атомарно заменяет `state` полным снимком и затем удаляет прежний контрольный файл.

Операции журнала начинаются с кода (`u8`) и ID узла (`u64`). Коды 0 и 1 создают каталог и файл, 2 удаляет узел, 3 меняет родителя и имя. Для создания и переименования следуют ID родителя, длина имени (`u8`) и имя UTF-8. Для нового файла дополнительно записывается 16-байтовое поколение. Код 4 задаёт размер файла, поколение, первый индекс и число записей (оба `u32`), затем пары из 32-байтового тега и смещения `u64`. Код 5 содержит логическое смещение `u64`, длину `u16` и до 4 096 байт замены внутри одного существующего блока. Журнал ограничен 256 операциями и 64 000 байтами операций. Общий бюджет сохранённых мелких правок составляет 512 000 байт с учётом полей. По мере заполнения и перед упаковкой эти правки сливаются с базовыми блоками.

Пустой узел может восстанавливаться по одному индексу. Предыдущие версии могут читать упакованный контейнер. Для возобновления сеанса с журналом нужна версия Linux с поддержкой журнала.

Изменённые блоки дописываются с выравниванием 4 096 байт. После сбоя
чтение опирается на смещения и теги зафиксированного индекса. Старые и
незафиксированные записи могут занимать место до уплотнения. При записи
рабочий файл уплотняется в новое поколение, если его размер превышает
размер актуального шифротекста более чем на максимум из 8 МБ и размера
актуального шифротекста. При упаковке в переносимый контейнер попадают
только актуальные записи в логическом порядке.

Временные рабочие файлы `pending-*` и промежуточный контейнер `packed` содержат только зашифрованные записи и открытые служебные заголовки. Рабочая папка относится к локальному сеансу. Для обмена между Linux и Windows используется закрытый файл `VLAGOST2`.

### Совместимость

Утилита принимает сигнатуру `VLAGOST2`. Снимки прежнего формата из версии прототипа с JSON этой утилитой не открываются. Раскладка использует 32-байтовый мастер-ключ. Парольный конверт для продуктового режима подлежит отдельному согласованию.

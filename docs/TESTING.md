# План проверок и текущие ограничения

## Приёмка VLAGOST2

- Проверить эталонный контейнер на обеих платформах и перенос после записи в
  обоих направлениях. Включить пустые файлы, вложенные каталоги, 1 МБ ровно,
  последний неполный блок и квоту в ГБ.
- Проверить неверный ключ, повреждение индекса, усечение, лишние байты,
  перестановку блоков и подстановку старого корректного блока в ту же позицию.
- Проверить зашифрованную рабочую копию при чтении, записи, конфликте имён,
  нехватке места, ошибке замены и сбоях до и после фиксации новой ревизии.

Для приёмки на Windows установите меню, используйте копию Linux-контейнера и Windows DLL поставщика. Проверьте чтение через границу 1 МБ, изменение и удаление файлов, повторное открытие, отказ при открытом на запись файле и повторную упаковку после закрытия редактора. После упаковки откройте контейнер на Linux и сравните дерево и хеши. Отдельно проверьте закрытие консоли провайдера во время сеанса и восстановление с тем же ключом. [Установка и команды](WINDOWS.md)

Ниже перечислены проверки утилиты Linux.

## Матрица VLAGOST2

| Проверка | Инструмент | Что проверяет |
|---|---|---|
| kuznechik_known_vector | Rust unit | Контрольный блок через плагин в ECB; контейнер использует CBC |
| kdf_rfc7836_vector | Rust unit | Контрольный вектор выработки 64 байт |
| roundtrip_tamper_wrong_key_and_random_iv | Rust unit | Длины 0/1/15/16/17/1024, свежий IV, неверный ключ, изменение байтов и усечение |
| tree_operations_persist_and_enforce_limits | Rust unit | Операции дерева, права, типы, ограничения, запрет удаления открытого файла |
| descriptor_survives_path_substitution_and_rejects_escape | Rust unit | Directory FD после подмены пути, запрет escape и symlink |
| workspace_recovery_and_ciphertext_transfer | Rust unit | Два блока, восстановление рабочей копии, перенос шифротекста, блокировка, неверный ключ и подстановка старого блока |
| cached_block_rejects_changed_ciphertext | Rust unit | Повреждение шифротекста выявляется при попадании в кэш по ID и номеру блока. Полная перезапись восстанавливает содержимое |
| resumes_cleanup_after_packed_revision_was_installed | Rust unit | Возобновление после успешной замены контейнера и отказа при очистке |
| crypto-only smoke | Python + PTY | CLI init/check, неверный ключ и повреждённый контейнер |
| Полный smoke | Python + Linux VM | Дополнительно FUSE, повторное открытие и bind mount подмена |
| Clippy | cargo clippy | Статические предупреждения всех целей корневого пакета |

Модульный тест дерева вызывает вспомогательные функции без настоящего
монтирования. Он не подтверждает работу callbacks через ядро.
Проверка отсутствия plaintext-подстроки в ciphertext — вспомогательная
регрессия, а не доказательство криптографической стойкости.

## Запуск полного сценария

В отдельной VM установите зависимости, соберите приложение обычным
пользователем и убедитесь в наличии /dev/fuse. Из корня проекта:

```bash
sudo python3 scripts/linux-smoke.py
```

Скрипт создаёт временное хранилище и случайный тестовый ключ, передаёт ключ
через PTY после отключения echo и не передаёт его в argv/env. Для дочерней
команды предусмотрен тайм-аут 90 секунд. Можно указать `--binary` и `--plugin`.
Режим `--crypto-only` не требует root и FUSE.

Полный сценарий запускает open с `--test`, затем `--verify`, затем тест с
`--attack`, и ещё раз verify. Встроенный тест создаёт/перезаписывает
`probe-persistent`; не используйте его как проверку рабочего хранилища.

## Дополнительные проверки для будущего развития

Следующие пункты — план, а не выполненные проверки: отказ диска перед/после
rename, ENOSPC и fsync failure; завершение процесса на границах сохранения;
повторные сигналы и занятой umount; тест видимого mount от sudo-пользователя;
проверка двоичного парсера методом фаззинга; длительная серия
открытий для диагностики плагина; проверка очистки ресурсов при ошибках.
Для принятия будущего изменения выбирайте проверки по затронутому поведению.

## Воспроизводимый замер записи через обработчики Linux

Из корня проекта запустите два раза на нужном томе:

```bash
VAULT_BENCH_DIR=. cargo test --locked --offline --release write_profiles -- --ignored --nocapture
```

Стенд создаёт отдельный временный контейнер для каждого профиля и использует штатный плагин. В интервал записи входит итоговая синхронизация. Упаковка измеряется отдельно. После повторного открытия стенд сравнивает все байты с оригиналом. Работа через ядро FUSE измеряется отдельно копированием в смонтированную папку.

## Проверка CFAPI на Windows

В сеансе пользователя с локальным временным каталогом на NTFS задайте путь к x64 DLL. Тест создаёт временный контейнер с отдельным ключом, трижды монтирует его, проверяет отказ закрытия при открытом редакторе, чтение и запись через границу 1 МБ, переименование, удаление и байты после повторного открытия.

```powershell
$env:VAULT_TEST_WINDOWS_DLL = 'C:\VaultLab\aldcrypto.dll'
cargo test --locked explorer_session_roundtrip -- --ignored --nocapture
```

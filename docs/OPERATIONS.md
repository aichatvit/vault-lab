# Эксплуатация и диагностика

В Windows каталог сеанса находится в профиле пользователя. При прерванной упаковке сохраните его вместе с исходным контейнером. Ниже описаны операции в Linux. [Установка и работа в Windows](WINDOWS.md) · [Диагностика Windows](WINDOWS.md#если-операция-не-удалась)

## Резервное копирование и восстановление VLAGOST2

После успешной упаковки и закрытия переносится или копируется один файл
контейнера. Мастер-ключ хранится отдельно. При нехватке места для упаковки
сохраняются исходный контейнер и зашифрованная рабочая копия. После
повторной аутентификации операцию можно продолжить. Для упаковки учитывайте
место под рабочую копию и новый контейнер одновременно с исходным.
[Порядок восстановления](ALGORITHMS.md#жизненный-цикл-vlagost2)

## Установка и проверка

Распакуйте ZIP, перейдите в `vault-lab`, установите зависимости по
[README](../README.md#сборка) и выполните `cargo build --locked`.
Архив содержит локальный крейт `crypto`, но остальные зависимости Cargo
при первой сборке могут потребовать доступ к реестру. Каталог `target` не включён.
Бинарный плагин предназначен для Linux x86-64; переносимость на другие платформы
и совместимость с любой версией системных библиотек не гарантируются.

Проверки: `cargo test --locked -- --test-threads=1`,
`cargo clippy --locked --all-targets -- -D warnings`,
`python3 scripts/linux-smoke.py --crypto-only`.
Полный сценарий: `sudo python3 scripts/linux-smoke.py` в отдельной Linux VM
с `/dev/fuse` и разрешёнными монтированиями. Результаты прежней поставки зафиксированы в [PACKAGING_REPORT](../PACKAGING_REPORT.md) и [TEST_REPORT](../TEST_REPORT.md).

Повторно открывайте контейнер с тем же ключом и от той же учётной записи,
которая вела сеанс. Служебная папка и файл блокировки нужны локально. При
восстановлении резервной копии поместите её под отдельным именем и выполните
`check` перед открытием. Для восстановления изменений после аварии сохраняйте
контейнер и его соседнюю рабочую папку как пару. `check` проверяет упакованную
ревизию, а `open` дополнительно проверяет и возобновляет рабочую копию.

## Диагностика

| Симптом | Проверка / действие |
|---|---|
| Плагин не найден | Запустите из корня проекта или задайте абсолютный `--plugin` |
| Ошибка bindgen/libclang | Установите clang, libclang и C++17 toolchain; проверьте пути заголовков |
| `Vault is busy` | Завершите другую сессию этого хранилища |
| Ошибка формата ключа | Введите ровно 64 hex-символа, без пробелов |
| Ошибка аутентификации | Проверьте ключ и целостность контейнера и рабочей копии; не редактируйте шифротекст |
| `createCryptoContextByParams: native error 507` | Основной контекст исчерпал повторные попытки с новым seed. Зафиксируйте версию и окружение плагина. При отказе только вспомогательного контекста утилита продолжает шифрование основным потоком |
| `openat2` недоступен | Нужен Linux 5.6+ и разрешение syscall в окружении; fallback отсутствует |
| Отказ mount / namespace | Проверьте root, `/dev/fuse`, разрешения VM/контейнера |
| Точка mount отклонена | Нужен существующий пустой каталог без символьных ссылок в пути |
| Каталог занят при umount | Закройте файлы и терминалы внутри точки, повторите размонтирование |
| Ошибка записи или упаковки | Освободите место при необходимости и снова откройте контейнер, сохранив рабочую папку |
| Конфликт ревизии | Сохраните рабочую папку и проверьте, какая версия контейнера была по исходному пути |

## Состав исходного комплекта

Код, Cargo.toml/Cargo.lock, скрипт smoke, документация, vendor/crypto и
lib/libaldcrypto.so включены. Локальные хранилища, расшифрованные данные,
настройки IDE, каталоги сборки и служебные настройки агента исключены.
Манифест архивной поставки проверяется из каталога распакованного ZIP командой
`sha256sum -c MANIFEST.sha256`.
Контрольные суммы обнаруживают изменение содержимого, но не заменяют подпись.
Права поставщика крейта и плагина сохраняются, см. [README](../README.md#права-на-компоненты).

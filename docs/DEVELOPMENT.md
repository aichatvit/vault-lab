# Руководство разработчика

## Реализация VLAGOST2

Сигнатура, двоичная раскладка и входы криптографических операций заданы в
[формате данных](DATA_FORMAT.md#vlagost2--формат-s-box) и
[ключевой схеме](KEY_MANAGEMENT.md#ключи-vlagost2). Для данных на диске
используйте целые числа байтов с проверкой переполнения. Преобразование в
десятичные МБ и ГБ выполняется на границе пользовательского интерфейса.
Совместимость Linux и Windows проверяйте на одних и тех же байтах контейнера.

## Состав и сборка

Rust edition 2024, минимальная версия в Cargo.toml — 1.87. Для Windows x64 нужны инструменты C++ и LLVM. [Сборка Windows](WINDOWS.md#установка)

Команды ниже относятся к Linux x86-64 с openat2 (ядро 5.6+) и FUSE. Инструкции установки
системных пакетов находятся в [README](../README.md#сборка).

```bash
cargo build --locked
cargo test --locked -- --test-threads=1
cargo clippy --locked --all-targets -- -D warnings
python3 scripts/linux-smoke.py --crypto-only
```

`--offline` можно добавить при уже заполненном Cargo cache. Наличие Cargo.lock
фиксирует Rust-зависимости, но не версию системного Clang или ABI плагина.
Корневой crate — бинарное приложение; публичного стабильного Rust API нет.
Unit-тесты располагаются внутри src-модулей. Тесты vendor/crypto имеют отдельные
инструкции в его tests/README.md и не являются автоматически проверенными
тестами корневого `cargo test`.

## Назначение зависимостей

| Компонент | Использование |
|---|---|
| crypto (path) | Управление ресурсами и ABI нативного плагина |
| bindgen (vendor build) | Генерация привязок из C++ заголовков |
| clap | CLI |
| fuser + libc | FUSE и Linux syscalls |
| getrandom | Ключи, ID, IV, имена временных файлов, seed контекста |
| rpassword | Скрытый ввод ключа |
| zeroize / subtle | Очистка управляемых секретных буферов / сравнение MAC |
| anyhow | Контекст ошибок |
| tempfile / hex | Временные каталоги и hex-кодирование |

Изменение в поставляемом crypto wrapper.hpp — include `<algorithm>` для
std::copy_n. Оригинальные заголовки поставщика не редактировались по README.
Не назначайте чужому крейту и бинарному плагину лицензию проекта.

## Изменения, требующие особого внимания

При несовместимом изменении формата определите новую сигнатуру и labels KDF. При изменении сохранения проверьте порядок fsync/rename и состояние
памяти после ошибок. При изменении путей сохраните использование directory FD
и флагов openat2. Не добавляйте неявный fallback на обычный open.

При изменении FUSE проверьте ограничения размера до выделения памяти,
семантику truncate, поведение poisoned и открытых файлов. При изменении
криптографии сохраните отдельные ключи, свежий IV и проверку MAC до decrypt.
Все утверждения о защите должны соответствовать [модели угроз](SECURITY.md).

## Выпуск комплекта

В поставку включаются src, scripts, docs, vendor, lib, Cargo.toml/Cargo.lock,
README и отчёты. Не включаются target, рабочие хранилища, plaintext,
конфигурация IDE и служебные файлы агента. Манифест SHA-256 охватывает все
файлы поставки, кроме самого себя. После изменения документации пересоберите
архив и манифест; старые контрольные суммы перестают описывать комплект.

Наличие `.so` в архиве не делает комплект независимым от системных библиотек.
Перед распространением за пределы локального тестирования необходимо иметь
права поставщика; открытая лицензия на компоненты здесь не объявляется.

## Сборка установщика MSI

На Linux потребуются Python 3.11+, `llvm-readobj`, `wixl` и `msibuild` из msitools. Из корня репозитория запустите сборку с путями к готовым x64 EXE и DLL поставщика.

```bash
python3 scripts/build-windows-msi.py --exe target/x86_64-pc-windows-gnu/release/vault-lab.exe --plugin /путь/к/aldcrypto.dll
```

Пакет появляется в `target/installer/VaultLab-<версия>-x64.msi`. Скрипт берёт версию из Cargo.toml и проверяет архитектуру и импортируемые DLL. Если обновлённые бинарники потребуют сторонний рантайм, сборка укажет его имя. При смене содержимого публикуемой версии увеличьте версию продукта для обновления через Windows Installer. [Состав MSI](../packaging/windows/VaultLab.wxs)

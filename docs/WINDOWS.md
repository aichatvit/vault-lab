# S-Box в Windows

Провайдер открывает существующий контейнер `VLAGOST2` как папку в Проводнике. После **Монтировать S-Box** можно читать и редактировать файлы. После **Размонтировать S-Box** изменения попадают в переносимый `.sbox`. Провайдер работает локально через Cloud Files API (CFAPI). Облачная учётная запись, WinFsp и отдельная буква диска для этого не нужны.

**Ограничение защиты.** Контейнер зашифрован. В рабочей папке NTFS видны имена и размеры файлов, Windows может сохранять расшифрованные байты, а приложения записывают туда изменения. Если на физическом диске разрешены только зашифрованные данные, защитите том профиля пользователя, например с помощью BitLocker. Учитывайте также тома с временными файлами приложений, подкачкой и экспортированными копиями. [Политики CFAPI](https://learn.microsoft.com/en-us/windows/win32/api/cfapi/ns-cfapi-cf_sync_policies) · [Шифрование томов BitLocker](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/)

## Что понадобится

- Windows x64 с работающим CFAPI и локальный профиль на NTFS. Microsoft указывает Windows 10 версии 1709 как минимум для клиентского API регистрации. Работа приложения на конкретных выпусках Windows 10, Windows 11 и Windows Server ещё требует проверки. [Требования CfRegisterSyncRoot](https://learn.microsoft.com/en-us/windows/win32/api/cfapi/nf-cfapi-cfregistersyncroot)
- Установщик `VaultLab-0.1.3-x64.msi`, либо готовый EXE, либо исходники. Для ручной регистрации меню скриптом нужен PowerShell 5.1 или новее. Запускайте команды от той учётной записи, которая будет работать в Проводнике. Регистрация меню выполняется в `HKCU` с обычными правами пользователя.
- MSI включает совместимую **Windows x64 DLL криптоплагина**. При ручной установке из EXE или сборке из исходников потребуется отдельная DLL поставщика. В исходном репозитории находится Linux-библиотека `lib/libaldcrypto.so`.
- Папка с правами на создание и замену файлов. Для открытия существующего контейнера потребуется его ключ. Потребуется место как в профиле, так и на томе контейнера.

## Установка

**Из одного MSI.** Откройте `VaultLab-0.1.3-x64.msi` в Windows из учётной записи, которой будете пользоваться в Проводнике. Установщик размещает EXE, криптоплагин и краткую инструкцию `S-Box.txt` в `%LOCALAPPDATA%\Programs\VaultLab` и регистрирует пункты меню для `.sbox`. Все три файла вложены в MSI. Для этой установки не требуется запускать скрипт, скачивать DLL или устанавливать Rust. Cloud Files API предоставляет Windows.

Для установки через командную строку выполните из каталога пакета следующую команду.

```powershell
msiexec.exe /i ".\VaultLab-0.1.3-x64.msi"
```

Перед обновлением или удалением размонтируйте контейнеры. Для удаления выберите **Vault Lab S-Box** в списке установленных приложений либо выполните `msiexec.exe /x ".\VaultLab-0.1.3-x64.msi"`. MSI удаляет свои файлы и регистрацию меню. Данные в `%LOCALAPPDATA%\VaultLab\sessions` и файлы контейнеров находятся вне каталога установки.

**С готовым EXE.** Разместите EXE и DLL в постоянном каталоге. В примерах это `C:\VaultLab`. В PowerShell из корня проекта запустите следующие команды.

```powershell
& 'C:\VaultLab\vault-lab.exe' --help
.\scripts\install-windows-explorer.ps1 -Executable 'C:\VaultLab\vault-lab.exe' -Plugin 'C:\VaultLab\aldcrypto.dll'
```

В справке должны появиться `S-Box Cloud Files provider`, `mount` и `unmount`. Если переносите кросс-сборку из рабочего дерева Linux, её путь после сборки — `target/x86_64-pc-windows-gnu/release/vault-lab.exe`. Параметр `-Plugin` принимает фактическое имя DLL поставщика. Сборочные инструменты для готового EXE не требуются.

**Из исходников на Windows.** Установите Rust stable x64 MSVC (версия Rust от 1.87), Visual Studio Build Tools с компонентами C++ и Windows SDK, а также LLVM с `libclang.dll`. Откройте x64 Developer PowerShell и перейдите в корень репозитория. Команды ниже предполагают стандартную установку LLVM и активный компилятор Rust с host `x86_64-pc-windows-msvc`. При другом расположении LLVM укажите каталог, где действительно лежит DLL. [Требования криптокрейта](../vendor/crypto/README.md)

```powershell
rustc -vV
$env:LIBCLANG_PATH = 'C:\Program Files\LLVM\bin'
cargo build --release --locked
.\target\release\vault-lab.exe --help
.\scripts\install-windows-explorer.ps1 -Plugin 'C:\VaultLab\aldcrypto.dll'
```

В этом варианте установщик берёт `target\release\vault-lab.exe` из проекта. Он регистрирует действия для одного выделенного файла в `HKCU\Software\Classes\SystemFileAssociations\.sbox\shell` и сохраняет абсолютные пути к EXE и DLL. Бинарники остаются на выбранных местах. Чтобы обновить их, сначала закройте сеансы. После перемещения EXE или DLL повторите установку с новыми путями. [Установщик Проводника](../scripts/install-windows-explorer.ps1)

## Как создать первый контейнер

В версии 0.1.1 и новее откройте нужную папку в Проводнике. Щёлкните правой кнопкой по **пустому месту** и выберите **Создать контейнер S-Box**. В Windows 11 пункт находится в классическом меню **Показать дополнительные параметры**. Введите имя, например `Работа`. Программа сгенерирует 32-байтовый ключ и покажет его в консоли. Сохраните все 64 символа отдельно от контейнера и вставьте их в запрос подтверждения. После подтверждения в папке появится `Работа.sbox` с квотой 1 ГБ. Существующие файлы защищены от перезаписи.

Ту же операцию можно выполнить из PowerShell. При необходимости задайте другую положительную квоту в десятичных ГБ.

```powershell
& "$env:LOCALAPPDATA\Programs\VaultLab\vault-lab.exe" create "$env:USERPROFILE\Работа.sbox" --quota-gb 1
```

## Работа в Проводнике

С версии 0.1.2 в левой панели Проводника есть постоянный пункт **S-Box**. После монтирования нажмите **S-Box** и дважды щёлкните ярлык с именем контейнера. Если открыты два одноимённых контейнера, второй ярлык получает числовой суффикс. Копируйте документы в папку, которая открывается через ярлык. Сам раздел **S-Box** содержит список ярлыков. После штатного размонтирования ярлык исчезает. Если при установке Проводник уже работал, откройте новое окно, а при необходимости выйдите из учётной записи и войдите снова.

1. Щёлкните правой кнопкой по одному локальному файлу `.sbox`. В Windows 11 откройте классическое меню через **Показать дополнительные параметры**. Выберите **Монтировать S-Box**.
2. Введите ключ в появившейся консоли. Ввод скрыт. Проводник откроет рабочую папку. Её точный путь также напечатан в строке `S-Box:`. Оставьте консоль открытой на всё время работы.
3. Создавайте, редактируйте, переименовывайте и удаляйте файлы внутри этой папки. Когда копирование или сохранение закончено и приложение закрыло файл для записи, провайдер шифрует его целиком в фоне. Следующее сохранение подготавливает новую полную версию. Для переноса между компьютерами нужна упакованная ревизия контейнера.
4. Сохраните документы, закройте редакторы и дождитесь завершения копирования. На **исходном файле** `.sbox` выберите **Размонтировать S-Box**. До окончания упаковки оставьте содержимое папки и сам контейнер на месте.
5. Дождитесь сообщения **«Контейнер сохранён и размонтирован.»** Теперь можно копировать контейнер, передавать его или извлекать носитель. Закрытие окна Проводника, консоли или завершение процесса не выполняет команду упаковки.

## Работа в PowerShell

После установки из MSI путь к EXE в PowerShell — `"$env:LOCALAPPDATA\Programs\VaultLab\vault-lab.exe"`. Для ручной установки в командах ниже используется `C:\VaultLab`. В первом окне запустите провайдер. Он выведет путь к папке и останется работать. Если DLL называется `aldcrypto.dll` и лежит рядом с EXE, параметр `--plugin` можно опустить. Флаг `--explorer` дополнительно открывает папку в Проводнике и включает диалоги с результатом операции.

```powershell
& 'C:\VaultLab\vault-lab.exe' --plugin 'C:\VaultLab\aldcrypto.dll' mount 'D:\Архивы\Работа.sbox'
```

Во **втором окне**, под той же учётной записью, выполните команду для того же файла. Ключ повторно вводить не требуется. Команда ждёт ответа работающего провайдера.

```powershell
& 'C:\VaultLab\vault-lab.exe' unmount 'D:\Архивы\Работа.sbox'
$LASTEXITCODE
```

Успешному закрытию соответствует код `0`. Чтобы удалить пункты меню, выполните из корня проекта команду ниже. Она убирает пункт **S-Box** и действия контекстного меню из реестра текущего пользователя. Активный сеанс завершается отдельно через `unmount`. EXE, DLL, контейнеры и данные сеансов остаются на своих местах.

```powershell
.\scripts\install-windows-explorer.ps1 -Uninstall
```

## Что хранится на диске

| Где | Что там находится |
|---|---|
| `%LOCALAPPDATA%\VaultLab\Containers` | Каталог, отображаемый как **S-Box** в левой панели. Ярлыки указывают на `opened` соответствующих сеансов. После аварийного завершения ярлык может сохраняться до восстановления и штатного закрытия. |
| Исходный `.sbox` | Последняя упакованная ревизия. До замены при размонтировании текущие правки находятся в рабочей папке. |
| `%LOCALAPPDATA%\VaultLab\sessions\<хеш пути>\base.sbox` | Полная зашифрованная копия исходной ревизии. Из неё провайдер читает данные для файлов-заполнителей. |
| `opened\` в том же каталоге сеанса | Рабочее дерево NTFS. При подключении появляются имена каталогов и файлов-заполнителей. Содержимое подгружается при чтении. Здесь могут лежать расшифрованные и изменённые данные. |
| Временные файлы в каталоге сеанса рядом с `opened` | По одному на подготовленную версию файла. Содержат только зашифрованные записи. Windows удаляет их при закрытии дескрипторов провайдера. После перезапуска подготовка повторяется из рабочей папки. |
| `lock`, `endpoint`, `ready`, `closing`, `retiring` | Служебные файлы блокировки, связи и этапов упаковки. `endpoint` содержит порт на `127.0.0.1` и токен команды закрытия. При диагностике не передавайте содержимое этого файла. Пустой каталог сеанса с `lock` может сохраняться после нормального закрытия. |
| Каталог исходного `.sbox` при упаковке | Новый контейнер. После успешной записи и синхронизации он заменяет исходный. |

Идентификатор каталога сеанса вычисляется из канонического пути к контейнеру. Для восстановления важны **тот же путь и та же учётная запись**. Папка `opened` содержит файлы-заполнители, для чтения которых может требоваться работающий провайдер. Резервную копию для переноса создавайте из закрытого `.sbox`.

## Ограничения

- **Чтение и кэш.** Политика `PARTIAL` позволяет обслуживать запросы диапазонами. Провайдер проверяет индекс при открытии и теги затронутых блоков при чтении. `STREAMING_ALLOWED` разрешает Windows обойтись без дискового кэша. Решение принимает ОС. После сбоя уже записанные в NTFS данные могут оставаться доступными согласно правам профиля. Обычное удаление рабочей папки при закрытии не обеспечивает гарантированного стирания её прежнего содержимого с носителя. [Семантика политик CFAPI](https://learn.microsoft.com/en-us/windows/win32/api/cfapi/ns-cfapi-cf_sync_policies)
- **Время закрытия.** При упаковке провайдер сверяет содержимое подготовленных файлов по SHA-256 и последовательно копирует готовый шифротекст. Для неизменённых файлов-заполнителей он проверяет теги и берёт записи из `base.sbox`. Если файл успели изменить, переименовать или скопировать непосредственно перед закрытием, недостающая версия шифруется при упаковке. Объём записи при закрытии соответствует целому новому контейнеру.
- **Свободное место.** На томе профиля нужны место для `base.sbox`, рабочей папки NTFS и зашифрованных версий новых или изменённых файлов. Пока готовится следующая версия файла, могут существовать обе. На томе контейнера требуется место для одной новой полной ревизии сверх исходной. Если это один том, расходы суммируются.
- **Квота.** Провайдер проверяет сумму логических размеров файлов при упаковке. Редактор может успешно записать файл, после чего `unmount` сообщит `S-Box quota exceeded`. 1 МБ равен 1 000 000 байт, 1 ГБ равен 1 000 МБ.
- **Имена.** Компонент пути занимает до 255 байт UTF-8. Провайдер отклоняет управляющие символы, запрещённые в Windows символы, завершающие пробелы и точки, а также имена устройств, например `CON.txt`, `NUL`, `COM1` или `LPT1`. При открытии проверяются совпадения имён в одном каталоге после перевода в верхний регистр. Контейнер с `Report` и `report` в одной папке потребуется исправить в Linux. [Правила имён Windows](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)
- **Свойства NTFS.** В контейнер переносятся дерево каталогов, имена и байты основного потока файлов. ACL, временные метки и отношения жёстких ссылок формат не сохраняет. Именованный поток (например, `Zone.Identifier`), символическая ссылка или junction в рабочей папке останавливают упаковку с диагностикой. Для переносимого снимка используйте обычные файлы и каталоги. [Поля индекса](DATA_FORMAT.md#зашифрованный-индекс)
- **Совместная работа.** Один процесс ведёт сеанс для данного пути. Открытый на запись файл или изменение состава каталога во время упаковки может помешать закрытию. Внешняя подмена контейнера вызывает ошибку. Подтверждённых результатов для сетевых папок, профиля в другом облачном каталоге и многопользовательского редактирования одной копии нет.

## Если операция не удалась

| Сообщение или симптом | Действие |
|---|---|
| Пунктов меню нет | Выберите один файл с расширением `.sbox`, проверьте классическое меню Windows 11. Выполните `--help` у выбранного EXE и повторите установку в текущем профиле. |
| `Cannot locate the Windows crypto DLL` или ошибка загрузки плагина | Проверьте путь, архитектуру x64, зависимости DLL и совместимость ABI у поставщика. После переноса DLL обновите регистрацию меню. |
| Ошибка ключа, формата или аутентификации | Введите ровно 64 hex-символа без пробелов. Проверьте, что это контейнер `VLAGOST2`. Ошибка проверки тега возможна как при неверном ключе, так и при повреждении данных. Полную проверку закрытой копии можно выполнить в Linux командой `check`. |
| `Cloud Files API HRESULT …` | Запишите полный шестнадцатеричный код, версию Windows и этап сбоя. Проверьте файловую систему тома профиля, доступ к рабочей папке и доступность Cloud Files. |
| `Session already active` или `Cannot open container for editing` | Проверьте, открыт ли уже провайдер, и есть ли права записи в контейнер. Для сохранения активного сеанса используйте `unmount` из того же профиля. |
| `Close applications using …` или `Directory changed during packing` | Закройте редактор и другие процессы, использующие указанный путь, дождитесь завершения копирования и повторите размонтирование. |
| Превышена квота или закончилось место | При превышении квоты сохраните лишние данные отдельно и уменьшите содержимое `opened`. При нехватке места освободите место на нужном томе. Сохраните каталог сеанса и повторите `unmount`. |
| `Named NTFS stream` или `Unsupported reparse point` | По указанному пути сохраните отдельно всё, что должно остаться за пределами контейнера, включая дополнительные потоки. Поместите в рабочее дерево обычный файл с нужным содержимым и повторите упаковку. |
| `Provider is offline`, `No active S-Box session` или консоль неожиданно закрылась | Сначала проверьте учётную запись и путь к исходному файлу. Если был незакрытый сеанс, снова выполните `mount` с прежним ключом по прежнему пути, затем `unmount`. |
| Снимок уже сохранён, но очистка прервана | Если процесс работает, повторите `unmount`. Если он завершился, снова выполните `mount`, затем `unmount`. При восстановлении после замены провайдер сверяет ещё оставшиеся файлы с сохранённой ревизией. Если появляется `Unsaved changes` или `Unsaved entry`, сохраните указанные данные отдельно перед устранением расхождения. |
| `Previous setup incomplete` или `Container changed outside this session` | Сохраните вместе исходный контейнер и каталог сеанса. При конфликте выясните, какая ревизия лежала по этому пути до подмены. Для прерванной **первичной** подготовки провайдер предлагает отложить весь каталог сеанса перед повторной попыткой. Удаление `base.sbox`, `opened` или маркеров вручную может лишить возможности восстановления. |

## Как проверить результат

1. На копии тестового контейнера откройте меню, подключите папку и запишите туда файл размером больше 1 МБ. Добавьте второй файл для проверки удаления. Запишите SHA-256 первого файла с помощью `Get-FileHash -Algorithm SHA256 -LiteralPath 'путь к файлу'`.
2. Размонтируйте контейнер через меню, дождитесь подтверждения и снова подключите. Сравните SHA-256 файла. Переименуйте его и удалите второй тестовый файл. После следующего закрытия и открытия проверьте новое имя, хеш и отсутствие удалённого файла. Для межплатформенной проверки откройте закрытый контейнер в Linux и сравните содержимое там.
3. Для автоматической проверки запустите тесты из корня проекта в Windows. Они используют временный каталог на NTFS и DLL криптоплагина. Первый тест проверяет закрытие при открытом на запись файле, изменение через границу 1 МБ и повторное монтирование. Второй проверяет перенос подготовленного шифротекста и сохранение последних правок при немедленном закрытии. Пункты меню и левую панель проверьте в Проводнике.

```powershell
$env:VAULT_TEST_WINDOWS_DLL = Join-Path $env:LOCALAPPDATA 'Programs\VaultLab\aldcrypto.dll'
cargo test --locked explorer_session_roundtrip -- --ignored --nocapture
cargo test --locked whole_file_staging_and_immediate_close -- --ignored --nocapture
```

Для версии 0.1.3 собраны Windows x64 EXE, MSI и исполняемый файл тестов. На Linux прошли 17 тестов, включая чтение на границе 1 МБ, побайтовый перенос зашифрованных записей и отказ при повреждении. Сквозной тест на Windows с NTFS, скорость размонтирования и перенос изменённого контейнера между системами ещё требуют проверки.

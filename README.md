# vault-lab 0.1.3

Тестовое приложение на Rust для Linux и Windows x64. Шифрование выполняет предоставленный
пользователем крейт `crypto`. Сборка Linux использует приложенный `lib/libaldcrypto.so`.
TPM, initrd и сторонняя реализация шифра не используются.

Это лабораторный прототип, не готовая система защиты от неограниченного root.
Работайте с тестовыми данными в отдельной VM.

Утилита Linux хранит данные в переносимом файле `VLAGOST2`. При открытии
она распаковывает зашифрованные записи в рабочую папку, а при закрытии
упаковывает изменения. Размеры и квоты указываются в десятичных МБ и ГБ.
В Windows установщик `VaultLab-0.1.3-x64.msi` включает программу и DLL криптоплагина. В Проводнике щёлкните правой кнопкой по пустому месту в папке и выберите **Создать контейнер S-Box**. После создания выберите **Монтировать S-Box** в меню файла `.sbox`. Рабочая папка доступна через раздел **S-Box** в левой панели.

После копирования или сохранения провайдер шифрует закрытый для записи файл целиком. При **Размонтировать S-Box** он собирает новый контейнер из проверенных зашифрованных записей и обрабатывает последние изменения. До подтверждения закрытия актуальные данные могут находиться только в профиле пользователя. В рабочей папке NTFS возможны открытые копии файлов. [Руководство для Windows](docs/WINDOWS.md) · [Установка и обновление](docs/WINDOWS.md#установка)

[Сценарий работы](docs/SBOX_WINDOWS_READER.md#общий-сценарий-работы-в-linux-и-windows) · [Спецификация](docs/DATA_FORMAT.md#vlagost2--формат-s-box)

В Astra Linux SE 1.7 пункты **Монтировать S-Box** и **Размонтировать S-Box**
доступны в контекстном меню Fly-FM после установки интеграции.
[Установка и совместимость криптоплагина](docs/SBOX_WINDOWS_READER.md#контекстное-меню-fly-в-astra-linux-se-17)

## Сборка

Ниже приведены команды для Linux. [Установка MSI и сборка Windows x64](docs/WINDOWS.md#установка)

Нужен Rust stable (не ниже 1.87), C++17, libclang, ядро Linux с openat2
(5.6+) и FUSE. Проект фиксирует зависимости в Cargo.lock. В этой среде
сборка проверена Rust 1.100.0 на Debian 13 x86-64.

Fedora:

```bash
sudo dnf install gcc gcc-c++ clang clang-devel fuse3 python3
cargo build --locked
```

Debian/Ubuntu:

```bash
sudo apt install build-essential clang libclang-dev fuse3 python3
cargo build --locked
```

Cargo запускайте обычным пользователем. Для `open` нужен root, поскольку
прототип создаёт приватное пространство монтирования. Разработка и тестирование
возможны из RustRover; операции FUSE запускайте в терминале VM через sudo.
Для `mount` также нужен root. Путь к плагину по умолчанию относителен текущему каталогу проекта.

Копия вашего крейта находится в `vendor/crypto`. Единственная правка:
в `wrapper.hpp` добавлен `#include <algorithm>`, необходимый для `std::copy_n`
из `mStringHelper_Linux.h`. Исходные заголовки поставщика не менялись.

## Запуск

Из каталога проекта:

```bash
# Напечатает случайный ключ один раз. Сохраните его отдельно.
./target/debug/vault-lab keygen

# Введите этот ключ: 64 hex-символа, ввод не отображается.
# Файла demo.sbox до init существовать не должно.
./target/debug/vault-lab init ./demo.sbox --quota-gb 1

# Проверка ключа и целостности без вывода содержимого.
./target/debug/vault-lab check ./demo.sbox

# Открыть FUSE и консольный клиент в приватном namespace.
sudo ./target/debug/vault-lab open ./demo.sbox
```

Чтобы открыть существующее хранилище `my-vault.sbox` в обычной папке:

```bash
mkdir -p ./opened
sudo ./target/debug/vault-lab mount ./my-vault.sbox ./opened
```

`my-vault.sbox` предварительно создаётся командой `init`. Папка `opened` должна
существовать, быть пустой и не содержать символических ссылок в пути.
Команда запрашивает ключ и работает на переднем плане. Монтирование видно
в текущем пространстве монтирования. Владельцем файлов становится пользователь,
запустивший `sudo` (через `SUDO_UID`/`SUDO_GID`): он может открыть `opened`
в файловом менеджере или выполнить `ls ./opened` без sudo. Права каталогов —
0700, файлов — 0600; остальные обычные пользователи доступа не получают.
При запуске непосредственно от root без sudo владельцем остаётся root.
Для закрытия нажмите Ctrl-C или выполните
`sudo umount ./opened` в другом терминале. Если папка занята, закройте открытые
файлы, выйдите из неё в других терминалах и повторите Ctrl-C.
Приватное пространство и передача дескриптора клиенту относятся к `open`;
режим `mount` предоставляет обычный путь для внешних программ.

Ключ — 32 случайных байта, НЕ пароль. Нет PBKDF, восстановления ключа или TPM.
Ключ запрашивается через терминал; аргумента `--key` нет. `keygen` выводит секрет
в терминал: не сохраняйте этот вывод в общедоступные журналы.
Для другого плагина: `--plugin /absolute/path/libaldcrypto.so`.
Плагин и его зависимости должны быть доверенными: загрузка `.so` исполняет код.

В открытой сессии:

```text
mkdir docs
put docs/note Привет, это тест
get docs/note
ls docs
exit
```

Поддерживаются `put PATH TEXT`, `get PATH`, `ls [PATH]`, `mkdir PATH`,
`mv PATH NEWPATH`, `rm PATH`, `rmdir PATH`, `exit`. Имена в клиенте без пробелов, только UTF-8.
`get` выводит данные в терминал: его scrollback не защищён хранилищем.
Клиент получает дескриптор корня FUSE, а не путь к общей папке.
Обычный файловый менеджер вне этой сессии не увидит монтирование.

Linux собирает изменения в памяти по блокам до 1 МБ, всего до восьми блоков
на сеанс. Чтение сразу видит изменения. Успешный `fsync` фиксирует записи
указанного файла в зашифрованной рабочей папке. До синхронизации или
штатного закрытия авария может привести к потере данных из буферов. `exit` завершает
клиент и снимает монтирование. При наличии изменений утилита собирает и
проверяет новый контейнер, затем атомарно заменяет файл. При прерванной
упаковке рабочая копия сохраняется для восстановления. `check` проверяет
последнюю уже упакованную ревизию.
[Восстановление](docs/OPERATIONS.md#резервное-копирование-и-восстановление-vlagost2)

## Тестирование

```bash
# Криптография использует настоящий приложенный .so, не mock.
cargo test --locked -- --test-threads=1
cargo clippy --locked --all-targets -- -D warnings

# CLI, ввод ключа через PTY, неверный ключ и повреждение контейнера.
cargo build --locked
python3 scripts/linux-smoke.py --crypto-only

# Полный тест внутри Linux VM с /dev/fuse. Ключ генерируется автоматически,
# передаётся в терминал и не выводится. Все данные тестовые и временные.
sudo python3 scripts/linux-smoke.py
```

Полный тест проверяет:

1. Создание, аутентификацию контейнера, отказ при неверном ключе.
2. FUSE: каталоги, запись, чтение, truncate, fsync, удаление.
3. Повторное открытие и чтение сохранённого файла.
4. Bind mount подставного пустого каталога поверх точки FUSE **после** получения
   дескриптора и **до** запуска клиента. Клиент продолжает работу с исходным FUSE,
   подставной каталог остаётся пустым.
5. Запрет выхода через `..` и отказ при повреждённом шифротексте.

Отдельные ручные сценарии (каждый запросит ключ):

```bash
sudo ./target/debug/vault-lab open ./demo.sbox --test
sudo ./target/debug/vault-lab open ./demo.sbox --verify
sudo ./target/debug/vault-lab open ./demo.sbox --test --attack
```

`--test` создаёт/перезаписывает тестовый файл `probe-persistent`.
Используйте отдельное тестовое хранилище.
Встроенный сценарий подмены — контролируемый эксперимент, а не обещание
защиты от root, активно управляющего процессами во время открытой сессии.

## Криптографический формат

Контейнер содержит заголовок, зашифрованный индекс и зашифрованные записи
файлов. Записи состоят из блоков до 1 МБ. Плагин выполняет шифрование
«Кузнечиком» в режиме CBC с PKCS#7 и HMAC-ГОСТ Р 34.11-2012-256. Приложение
проверяет теги до расшифровки. Индекс и каждый файл используют раздельные
пары ключей, полученные через KDF_TREE. Рабочие копии блоков совпадают с
записями в контейнере.
[Раскладка](docs/DATA_FORMAT.md) · [Ключевая схема](docs/KEY_MANAGEMENT.md)

## Защита пути и отказов

- Новый mount namespace; `MS_REC | MS_PRIVATE` для `/`.
- Новый приватный tmpfs и созданная службой точка FUSE внутри него.
- Приложению передаётся открытый дескриптор проверенного FUSE-корня.
- `openat2`: BENEATH, NO_SYMLINKS, NO_XDEV. Никакого небезопасного fallback
  на старые ядра. Сам root-дескриптор получен из доверенного монтажа;
  `fstatfs` — дополнительная проверка типа, не криптографическая аутентификация.
- Работа с backing-каталогом тоже относительно закреплённого дескриптора;
  ссылки в пути каталога не допускаются.
- `flock` исключает случайный одновременный запуск двух экземпляров. Это не
  защита от root, намеренно удаляющего/заменяющего файл блокировки.
- Программа дописывает группы зашифрованных блоков и атомарно публикует изменения индекса. Мелкая синхронная правка также может храниться в зашифрованном журнале до слияния с блоком.
- Закрытие: проверенная новая упаковка → атомарная замена контейнера → fsync каталогов.
- При ошибке фиксации индекса экземпляр прекращает выдачу данных.
  Повторное открытие проверяет контейнер и сохранённое состояние.
- При ошибке монтажа клиент не запускается. У клиента нет пути для записи
  в незашифрованную папку вместо FUSE.

## Границы прототипа

Доверяем ядру, бинарнику, плагину, конфигурации и пути запуска. Получение ключа,
предварительная подмена исполняемого кода и вмешательство root во время открытой
сессии исключены из модели угроз. Root при закрытом хранилище может копировать,
портить, удалять и откатывать зашифрованный контейнер, но не знает ключа.

Нет защиты от root, который читает память, внедряет код, входит в namespace,
перехватывает терминал или управляет процессами во время работы. Нет защиты
от физической памяти, swap, гибернации и гипервизора. Для тестовой VM отключите
swap/гибернацию, если проверяете отсутствие plaintext вне памяти. `zeroize` очищает
управляемые приложением секретные буферы, но не гарантирует очистку всех копий
плагина, аллокатора, ядра и терминала. Core dumps отключены; это не граница от root.

Квота задаётся на контейнер и по умолчанию равна 1 ГБ. Размер открытого
индекса ограничен 64 МБ. Изменённые блоки дописываются в рабочий файл,
а их смещения сохраняются в зашифрованном индексе. Если рабочий файл
разрастается, утилита уплотняет его. Поддерживаются перенос и переименование. Ссылки, mmap, xattr,
пользовательские права, времена файлов и POSIX-блокировки за рамками
прототипа. Удаление открытого файла возвращает EBUSY. Последовательность
запросов записи одного приложения может оставить зафиксированную частичную
версию файла.

## Права на компоненты

Архив включает предоставленные пользователем крейт и бинарный криптоплагин для
его локального тестирования. Права и ограничения поставщика сохраняются;
открытая лицензия этим компонентам не назначается. Не публикуйте их автоматически.

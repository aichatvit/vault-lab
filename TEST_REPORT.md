# Проверка vault-lab 0.1.0

Дата: 2026-11-13. Среда: Debian 13, Linux x86-64, Rust 1.100.0.
Использован приложенный пользователем настоящий libaldcrypto.so.

Сборка: выполнена. Clippy с `-D warnings`: выполнен.

Автоматические тесты:

- Контрольный вектор «Кузнечика».
- Контрольный вектор KDF_TREE RFC 7836 через HMAC плагина.
- CBC + HMAC round-trip для пустых, неполных и полных блоков.
- Новый IV при повторном шифровании.
- Отказ при неверном ключе, усечении и изменении заголовка/IV/шифротекста/MAC.
- Сохранение, повторное открытие снимка, блокировка второго экземпляра.
- Закреплённый directory FD после переименования и подмены исходного пути.
- Отказ при выходе через `..` и символьную ссылку.
- Операции дерева FUSE без монтирования: создание/размер/удаление/ограничения.
- CLI через PTY: создание, проверка, неверный ключ, повреждение снимка.

Полный FUSE smoke НЕ запускался: окружение не предоставляет /dev/fuse и
CAP_SYS_ADMIN. Проверка реального монтирования, bind mount атаки, FUSE callbacks
через ядро, размонтирования и Ctrl-C остаётся для Linux VM пользователя.
Сценарий: `sudo python3 scripts/linux-smoke.py`.

Исправлена одна Linux-ошибка сборки исходного крейта: отсутствие include
<algorithm> для std::copy_n. Исправление только в vendor/crypto/wrapper.hpp.

В среде сборки libclang есть, но отсутствует стандартный resource-dir Clang.
Локально использован BINDGEN_EXTRA_CLANG_ARGS с include-каталогом GCC 14.
На обычной Fedora с clang/clang-devel этот обход обычно не нужен.
